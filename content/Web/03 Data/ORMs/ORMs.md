## Cheatsheet

### Object State Is Not Database State

SQLAlchemy's Session holds an identity map and a unit of work. Changing an attribute marks an object dirty; flush emits SQL but does not commit. Autoflush can run before a query and expose a constraint failure earlier than the explicit commit. A failed flush requires rollback before reusing the Session. Use a short-lived Session per unit of work, not a global instance shared by requests or concurrent tasks.

`with Session(engine) as session, session.begin():` commits on normal exit and rolls back on exception. Expired attributes may query again after commit; a detached object may be unable to load them. Serialize explicit response projections while the intended data is available. The identity map is not an authorization cache: an object loaded earlier under another context can survive a later query-filter change.

### Relationships and Query Translation

| Strategy | Cost / failure mode |
|---|---|
| Lazy relationships | One query per accessed parent collection; serializers can trigger N+1 implicitly. |
| `selectinload(Parent.children)` | Parent query plus child IN query, possibly batched at larger sizes; avoids joined row multiplication. |
| `joinedload` on collections | One joined result but duplicates parent rows; SQLAlchemy 2.0 requires `unique()` when consuming such results. |
| Explicit column projection | Small stable response shape, no accidental lazy loading; write a deliberate join/aggregate. |
| Bulk UPDATE/DELETE | Bypasses some object-level hooks and relationship behavior; enforce policy and database constraints explicitly. |

Expressions such as `Model.name == value` normally bind values. Dynamic property lookup, raw SQL and string-built ordering are separate trust decisions. A join can multiply rows; counting ORM objects is not necessarily counting SQL rows. Inspect SQL plus parameters in development, but redact sensitive values in production logs.

```python
from sqlalchemy import text

statement = text("SELECT id, name FROM project WHERE name=:name")
```

Execute with `session.execute(statement, {"name": supplied_name})`; never format the name into `text()`. Identifiers require a fixed mapping to ORM columns. Database constraints remain essential: Python-side checks race under concurrency.

### Migrations and Compatibility

`metadata.create_all()` creates missing tables; it is not a schema migration system. Alembic revisions record schema transitions, but autogenerated output must be reviewed for renames, destructive changes, server defaults and data movement. Migration credentials may need DDL; the runtime account should not inherit that privilege. SQLite itself has no database login system, so its corresponding boundary is the process/file ACL.

Illustrative Alembic revision body, not part of the runnable lab:

```python
import sqlalchemy as sa
from alembic import op

def upgrade():
	op.add_column("project", sa.Column("display_name", sa.String(80), nullable=True))

def downgrade():
	op.drop_column("project", "display_name")
```

An expand/backfill/contract rollout first adds a compatible nullable column, deploys writers, backfills bounded batches, switches reads and only later removes the old field. Downgrade can lose data and is not automatically a safe rollback. SQLite table-rebuild migrations and online DDL in server engines have different locking/failure behavior; test against the deployment engine, not only SQLite.

## Gotchas

ORM parameterization does not authorize rows. Global filters may be bypassable by privileged APIs or raw queries.

### File: test_example.py

```python
import sqlite3
import unittest
import sqlalchemy
from sqlalchemy import ForeignKey, String, create_engine, event, select
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column, relationship, selectinload


class Base(DeclarativeBase):
	pass


class Project(Base):
	__tablename__ = "project"
	id: Mapped[int] = mapped_column(primary_key=True)
	name: Mapped[str] = mapped_column(String(80))
	tasks: Mapped[list["Task"]] = relationship(back_populates="project")


class Task(Base):
	__tablename__ = "task"
	id: Mapped[int] = mapped_column(primary_key=True)
	project_id: Mapped[int] = mapped_column(ForeignKey("project.id"))
	label: Mapped[str] = mapped_column(String(80))
	project: Mapped[Project] = relationship(back_populates="tasks")


class ORMMechanisms(unittest.TestCase):
	def setUp(self):
		self.engine = create_engine("sqlite://")
		@event.listens_for(self.engine, "connect")
		def enable_foreign_keys(connection, record):
			connection.execute("PRAGMA foreign_keys=ON")
		Base.metadata.create_all(self.engine)
		with Session(self.engine) as session, session.begin():
			session.add_all([
				Project(id=1, name="first", tasks=[Task(id=1, label="a")]),
				Project(id=2, name="second", tasks=[Task(id=2, label="b")]),
			])
		self.statements = []
		@event.listens_for(self.engine, "before_cursor_execute")
		def capture(connection, cursor, statement, parameters, context, many):
			self.statements.append(statement)

	def tearDown(self):
		self.engine.dispose()

	def test_loading(self):
		with Session(self.engine) as session:
			parents = session.scalars(select(Project).order_by(Project.id)).all()
			self.assertEqual([len(parent.tasks) for parent in parents], [1, 1])
		self.assertEqual(len(self.statements), 3)
		self.statements.clear()
		with Session(self.engine) as session:
			parents = session.scalars(select(Project).options(selectinload(Project.tasks))).all()
			self.assertEqual(sum(len(parent.tasks) for parent in parents), 2)
		self.assertEqual(len(self.statements), 2)

	def test_rollback_and_projection(self):
		with Session(self.engine) as session:
			project = session.get(Project, 1)
			project.name = "O'Reilly"
			session.flush()
			self.assertEqual(session.scalar(select(Project.name).where(Project.id == 1)), "O'Reilly")
			session.rollback()
		with Session(self.engine) as session, session.begin():
			self.assertEqual(session.get(Project, 1).name, "first")
			payload = {"name": "approved"}
			if set(payload) != {"name"}:
				raise ValueError("unexpected field")
			session.get(Project, 1).name = payload["name"]
		with Session(self.engine) as session:
			self.assertEqual(session.execute(select(Project.id, Project.name).order_by(Project.id)).all(), [(1, "approved"), (2, "second")])


if __name__ == "__main__":
	print("SQLAlchemy", sqlalchemy.__version__, "SQLite", sqlite3.sqlite_version)
	unittest.main()
```

### Objectives, Hints, and Solution

Predict SQL counts and identify the flush/commit boundary. Hint: use a fresh Session for each loading strategy; otherwise a populated identity map hides lazy loads. Expected: two tests pass, lazy loading issues three statements for two parents, select-in loading issues two. Flush makes the temporary value visible inside its transaction; rollback discards it. Explicit projection returns only IDs/names and the approved update persists.

### Troubleshooting and Cleanup

Unexpected counts often come from event registration before schema/seed work or reuse of a populated Session. The two-query expectation is scoped to this tiny fixture, not every number of parents. SQLite enforcement is enabled per connection. In-memory databases and engines close automatically; the only persistent lab artifact is the local virtual environment, which can be removed after leaving it. No migration or cross-engine deployment result is claimed.
